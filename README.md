# UX Research Toolkit

用户研究与人因工程的方法工具化沉淀——把可标准化的环节交给工具，让时间回到判断本身。

这里记录我在用研工作中反复遇到的问题，以及为此做出来的工具。面向同行交流，欢迎指正。

---

## AI 在工作流里该站在哪里

做工具的起点不是"AI 能做什么"，而是"交给 AI 之后，结论还站不站得住"。

据此可以把用研流程拆成两类环节：**能用明确规则判定对错、且出错容易被发现的，可以交给工具；需要承担判断责任的，留在人手上。**

| 环节 | 可交给工具 | 需由人保留 |
|---|---|---|
| 研究问题定义 | 文献脉络梳理、既有研究缺口汇总 | 问题本身的取舍与优先级 |
| 抽样与招募 | 招募文案草拟、筛选条件清单生成 | 抽样策略、目标人群界定 |
| 工具设计（问卷 / 提纲） | 初稿生成、引导性与偏差自查 | 条目效度判断、量表结构决策 |
| 数据收集 | 转写、说话人分离 | 访谈中的追问与临场判断 |
| 数据整理 | 清洗、分段、词频统计 | — |
| 分析（编码） | 编码初稿、范畴归并候选 | 编码框架的立场选择、最终确认 |
| 洞察提炼 | 证据归集、反例检索 | 意义阐释、优先级判断 |
| 报告与决策转化 | 结构化填充、格式转换 | 建议的可执行性与责任承担 |

这份划分不是恒定的。随着工具能力变化，边界会移动；但**结论的最终判断权不移交**，这是我的底线。

## 工具

### Interview Insight · 访谈文本结构化洞察

[→ interview-insight](https://github.com/ux-student/interview-insight)

把访谈逐字稿转成可复核的洞察报告。重点不在"生成得快"，而在**换个人来复核，结论还在**。

**它做什么**

- **预处理**：分离访谈者 / 受访者发言，清洗语气词，输出带段落编号 `[S编号]` 的可溯源文本
- **三级编码框架**：开放编码 → 轴心编码 → 选择编码，统一五大范畴——用户与场景 / 功能体验 / 交互体验 / **物理体验（人因）** / 态度与期望
- **洞察五要素**：结论 + 频次 + 原话佐证 + 业务启示 + **反例检索结果**，缺一不可
- **影响程度分级**：1–4 级行为锚点（看行为，不看形容词），与分布广度**分列呈现，不做乘积合成**
- **中间产物全部落盘**：报告可沿「洞察 → 轴心范畴 → 开放编码 → 段落编号 → 原始逐字稿」逐层反查

**它不做什么**（这部分和功能同等重要）

- 不做编码者间一致性检验——单编码者流程，因此不报告 Kappa / Alpha
- 不承担理论建构——不判定理论饱和，不生成理论
- 不做语音识别与说话人分离，输入须为已转写文本
- 不替代研究者判断——分级、命名、阐释由工具给出候选与证据，确认权在人

**几个值得一提的设计选择**

- **频次不等于重要性**。"提到的人多"与"问题更要紧"是两件事，工具分列呈现，不做合成排序
- **强制找反例**。只收集支持性证据会系统性放大已有结论；未找到反例也须写明检索范围，空栏位视为流程未完成
- **看行为，不看形容词**。用户说"特别烦"但未影响任务，仍是低级别；一句"还行吧"若伴随弃用行为，级别反而高
- **区分"清洗后文本"与"逐字原话"**。报告中的引文来自清洗后文本，需逐字引用时须回原始逐字稿

## 规划中

- **问卷生成与信度预检**：标准化问卷生成，配套信效度预检
- **访谈提纲库**：半结构化访谈框架与追问体系

方向是一致的：继续把确定性环节自动化，把判断留给人。

---

## 设计原则

- **专业主导**：工具只承担确定性、重复性的环节。结合业务语境的洞察与判断，由研究员完成
- **可溯源**：结论必须绑定频次与原始证据，不接受无依据输出
- **可复核**：中间过程留痕。AI 生成的分析最容易受到的质疑是"结论看着成立，但无法验证"——留痕是让结论能被追问的前提
- **数据隐私**：真实研究数据不进入仓库，示例仅使用虚构数据
